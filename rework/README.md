# rework — 리버스 엔지니어링 워크벤치

한국어 사용자를 위한, 쓰기 쉬운 리버스 엔지니어링 도구입니다. 바이너리(ELF·PE·Mach-O)를
열어 **함수·문자열·심볼을 훑고, 디스어셈블리와 의사코드(디컴파일)를 나란히 보며, 이름·주석을
붙여 가며** 분석합니다. AI 도우미에게 함수 설명을 물어볼 수도 있습니다.

> 상태: 1차 버전(작동하는 코어). Ghidra·IDA를 대체하는 완성품은 아니며, 분석가가 큰 흐름을
> 빠르게 잡도록 돕는 데 집중했습니다. 아래 **로드맵** 참고.

## 설치(데스크톱 앱)

**Kali·Ubuntu·Debian**: `rework-<버전>-linux-amd64.deb`(권장) 또는 `rework-<버전>-linux-x86_64.AppImage`.
`.deb` 는 `gdb`·`bubblewrap` 을 의존성으로 받아 디버거와 격리 실행이 바로 동작합니다.

```bash
sudo apt install ./rework-0.1.0-linux-amd64.deb && rework        # 또는 메뉴의 rework
chmod +x rework-0.1.0-linux-x86_64.AppImage && ./rework-0.1.0-linux-x86_64.AppImage   # AppImage 는 gdb·bubblewrap 을 직접 설치
```

**Windows**: `rework Setup <버전>.exe`. 정적 분석(디스어셈블·디컴파일·문자열·심볼)은 바로 되고, 디버거·격리 실행은 리눅스 전용이라
메뉴 **실행 환경 > WSL2** 로 전환해 쓰세요([아래](#데스크톱-앱-windowskali)).

개발 중에는 설치 없이 아래 [빠르게 실행](#빠르게-실행)(브라우저) 또는 `cd desktop && npm install && npm start`(앱 창).

## 빠르게 실행

필요: Python 3.11+ (리눅스·Windows·macOS). 동적 분석(디버거)에는 **GDB**가 추가로 필요합니다
(`apt install gdb` / Windows는 MSYS2·WSL 등의 gdb). 디버거를 안 쓰면 GDB 없이도 정적 분석은 모두 됩니다.
디버깅 대상을 **격리해서 실행**하려면 리눅스에서 **bubblewrap**도 설치하세요(`sudo apt install bubblewrap`,
Kali 포함 — 아래 [격리 실행](#격리-실행-샌드박스)).

```bash
cd rework
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt   # Windows: .venv\Scripts\pip
.venv/bin/python run.py                              # 기본 127.0.0.1:8777 (로컬 전용)
```

브라우저에서 <http://127.0.0.1:8777> 을 엽니다. 왼쪽 **열기**에서 로컬 파일을 고르거나 끌어다
놓으면 분석이 시작됩니다. 바로 써 볼 수 있도록 `samples/demo_elf`(작은 데모 바이너리)를 넣어
두었습니다.

## 소스 편집 (작업 폴더·Monaco)

탐색기(`Ctrl+Shift+E`)에서 **작업 폴더**를 열면(경로 입력 · 최근 폴더 · 폴더 고르기 · 데스크톱은 메뉴 **파일 > 폴더 열기** 또는 폴더 끌어다 놓기) 그 안의 텍스트 파일을 편집할 수 있습니다.
분석 화면과 같은 탭에서 함께 쓰므로 바이너리 함수를 보다가 소스 탭으로 오가며 작업할 수 있습니다.

| 항목 | 내용 |
| --- | --- |
| 편집기 | **Monaco 0.52.2** 를 `frontend/vendor/monaco/` 에 **포함(오프라인 동작)** 합니다. 해시를 고정해 내려받는 `scripts/vendor_monaco.py` 로 갱신. 한국어 UI·구문 강조·자동완성·코드 접기·여러 커서·찾기/바꾸기·미니맵. 엄격한 CSP(`script-src 'self'`) 아래에서 같은 출처 작업자(`worker.js`)로 돕니다 |

## 디버거 (동적 분석)

좌측 **디버그**(벌레 아이콘) 또는 `F5`로 시작합니다. 요구 사항: 시스템에 **GDB가 설치**되어 있어야
합니다(`apt install gdb`). 시작하면 `main`에 중단점을 걸고 거기서 멈춥니다. 심볼이 없어 `main`을
못 찾는(스트립된) 바이너리는 중단점 없이 실행되고 알림이 뜹니다. 이때는 `⏸ 멈춤`으로 중단하거나
`+`로 `*0x주소` 중단점을 먼저 거세요.

- **중단점**: 디버그 사이드바의 `+`(함수명·`*0x주소`·`파일:라인`), 또는 디버거 탭의 라이브
  디스어셈블리에서 줄을 클릭해 토글. 체크박스로 사용/해제, `×`로 삭제. `+` 대화상자에서 **조건**(`i == 3`, 참일 때만 멈춤)·**처음 N 번 건너뛰기**·
  **한 번만 멈추고 삭제(임시)** 를 줄 수 있고, 목록의 `✎`로 나중에 조건을 바꾸거나 지웁니다. 조건이 틀린 식이면 달지 않고 이유를 알려 줍니다.
  디스어셈블리에서 `Alt+클릭`하면 그 주소까지 실행(임시 중단점)합니다.
- **로그포인트**(`✎` 버튼): 멈추지 않고 메시지만 찍습니다(gdb `dprintf`). `i=%d name=%s` 처럼 printf 형식과 인자 식을 주면 디버그 콘솔에 출력되고, 조건도 줄 수 있습니다.
- **워치포인트**(`👁` 버튼): 변수·`*주소` 식의 값이 **바뀔 때**(또는 **읽힐 때**·**접근될 때**) 멈추고, 정지 띠에 `값이 바뀜: 3 → 6` 처럼 옛 값·새 값을 보여 줍니다.
  조건, 그 변수가 있는 *주소*를 감시(지역 변수가 사라져도 유지), 하드웨어 감시를 못 쓸 때의 소프트웨어 감시(매우 느림)를 고를 수 있습니다.
- **스택·메모리·감시식**(디버거 탭 오른쪽 탭): ‘스택’은 호출 스택(프레임을 클릭하면 레지스터·지역변수·디스어셈이 그 프레임 기준으로 바뀜)과 `$sp`부터의 **스택 메모리**를
  보여 주고, 각 칸이 코드(`함수+오프셋`)·스택·힙·데이터 포인터인지, **반환 주소**인지, 가리키는 문자열이 무엇인지 덧붙입니다(값을 클릭하면 메모리 탭으로).
  ‘메모리’는 주소·식(`$sp`, `&buf`)·영역(`[stack]`, 라이브러리 등)으로 이동하는 16진 덤프로, 바뀐 바이트를 강조하고 **더블클릭해 바이트를 직접 씁니다**.
  ‘감시식’은 멈출 때마다 다시 계산되는 식 목록(더블클릭해 값 수정).
- **역방향 디버깅**: 중단점에서 멈춘 뒤 `⏺ 기록 시작`을 누르면 gdb 가 이후 실행을 기록하고(느려짐), `⏪`(거꾸로 계속)·`◀↓`·`◀⤼`·`◀»`·`◀⤴` 로 되돌아갈 수 있습니다.
  기록은 시작한 시점부터만 있고, 일부 명령(AVX 등)은 gdb 가 기록하지 못해 거기서 멈춥니다.
- **원격 gdbserver**: 시작 카드의 ‘원격 gdbserver 에 연결’에 `host:port` 를 주면, 프로그램은 원격(보드·VM)에서 실행되고 여기서 연 바이너리는 심볼 해석에 쓰입니다.
  서버가 토큰 인증(`--require-token`)일 때만 허용되고, 이때만 gdb 에 호스트 네트워크를 열어 줍니다(원격에서 도는 프로그램이라 로컬에는 대상 프로세스가 없습니다).
  `| 명령` 같은 파이프·직렬 장치 경로는 받지 않습니다.
- **실행 제어**: 계속(`F5`) · 한 줄 넘어(`F10`) · 한 줄 안으로(`F11`) · 명령 단위(stepi) ·
  함수 끝까지(`Shift F11`) · 멈춤 · 정지(`Shift F5`). 프로그램이 끝나면 `↻ 다시 실행`(`F5`)으로
  같은 인자로 다시 돌릴 수 있습니다.
- **상태**: 레지스터(바뀐 값 강조), 콜스택, 지역변수·인자를 실시간 표시.
- **런타임 조작**: 레지스터·지역변수 값을 더블클릭해 바꾸면 프로그램 흐름이 실제로 달라집니다.
  디버그 콘솔에서 원시 gdb 명령(`x/16xb $sp`, `set $rax=1`, `info proc mappings` 등)도 쓸 수 있습니다.
- **대상 입출력**: 프로그램의 stdout/stderr는 전용 pty로 캡처되어 **디버그 콘솔** 탭에 gdb 메시지와
  **도착 순서대로** 섞여 표시됩니다. 같은 탭의 **입력 ▸** 줄이 대상 프로그램의 stdin입니다.
  - `Enter`로 전송(`줄바꿈` 체크 시 끝에 개행을 붙임), `↑↓`로 이전 입력 불러오기. 한글 입력(IME 조합 중
    Enter는 전송되지 않음)도 그대로 전달됩니다. 터미널과 같은 쿠킹 모드라 입력한 글자가 에코로 보입니다.
  - `EOF` 버튼은 `^D`를 보내 “입력 끝”을 알립니다(`fgets`가 NULL을 받는 경우 등).
  - `\x 해석`을 켜면 `\n`·`\xHH`·`\033` 같은 이스케이프를 바이트로 풀어 보냅니다(제어·바이너리 입력).
  - **보낸 바이트가 그대로 프로그램에 도착합니다.** 터미널이 입력을 멋대로 해석하지 않도록 시작할 때
    신호(`ISIG`)·흐름제어(`IXON`)·CR 변환을 꺼 두고, 그래도 해석되는 `^D`·`0x7f`·`^U` 같은 바이트는
    터미널의 리터럴 인용(`^V`)으로 감싸 보냅니다. 그래서 `^C`·`^Z`·`^\`·`^S` 바이트가 들어 있어도 디버기가
    멈추거나 죽지 않고 출력이 얼지도 않으며, 바이너리 페이로드가 변형되지 않습니다. (프로그램을
    멈추려면 `⏸ 멈춤`을 쓰세요. 입력으로는 신호가 가지 않습니다.)
  - **한 줄은 4095바이트까지**입니다. 터미널(pty)이 그보다 긴 줄을 조용히 잘라 버리기 때문에, 넘으면
    잘린 입력으로 분석하지 않도록 **전송 전에 거부**합니다. 긴 페이로드는 파일로 만들어 실행 인자에
    `< 입력파일`을 쓰세요(제한 없음).
  - 프로그램이 입력을 읽지 않아 터미널 버퍼가 가득 차면 3초 안에 오류로 돌려줍니다(서버가 걸리지 않음).
    일부만 전달됐다면 몇 바이트가 이미 들어갔는지 알려 주고, 다음 입력의 줄 길이 계산에도 반영합니다.
  - 입력은 프로그램이 **실행 중이거나 중단점에서 멈춰 있을 때만** 받습니다. `실행` 때마다 이전 실행에서
    안 읽힌 입력과 바뀐 터미널 모드를 초기화하므로 입력이 다음 실행으로 새지 않습니다.
  - 프로그램이 스스로 터미널을 raw 모드로 바꿨다면 줄 단위 해석이 없으므로 4095바이트 제한이 적용되지
    않고(`EOF` 버튼은 의미가 없어 거부), cooked 로 돌아오면 다시 제한이 적용됩니다.

> ⚠ **디버깅은 대상 바이너리를 실제로 실행합니다.** 기본값은 아래 **격리 실행**이고, 격리를 쓸 수 없거나
> 끄면 이 컴퓨터에서 그대로 실행됩니다. 서버는 127.0.0.1에만 바인딩됩니다.

## 격리 실행 (샌드박스)

디버그 사이드바의 **격리 실행** 카드에서 상태를 보고 설정합니다. 기본이 켜져 있으며, **gdb 와 대상
프로그램이 모두** [bubblewrap](https://github.com/containers/bubblewrap) 안에서 실행됩니다.

| 보호 | 내용 |
| --- | --- |
| 네임스페이스 | 프로세스·네트워크·IPC·호스트명·사용자 분리. 호스트 프로세스가 보이지 않고, 대상 안에서 새 user namespace 를 만들 수 없음 |
| 파일시스템 | 읽기 전용 최소 루트(`/usr` 일부만). 홈·`/etc`·rework 데이터(API 키)·`/run` 등은 보이지 않음. 루트·`/dev` 읽기 전용, 쓸 곳은 크기가 정해진 `/tmp`·`/dev/shm` 뿐 |
| 대상 파일 | 원본이 아니라 **읽기 전용 복사본**을 실행(원본은 잠기지 않고 변조되지 않음). 복사본은 샌드박스 사용자만 읽을 수 있음(0500) |
| 네트워크 | 기본 차단(자기 루프백만). 호스트 소켓·추상 유닉스 소켓·외부 통신·`AF_PACKET` 불가 |
| 환경 | 환경 변수를 비움(API 키 등이 새지 않음), 합성 `/etc/passwd`, capability 전부 제거, no-new-privs |
| 낮은 uid | rework 가 root 로 돌면 `nobody`(65534)로 낮춰 실행(탈출해도 root 가 아님). 일반 사용자로 돌면 낮추지 않으며 보고서에도 그렇게 표시 |
| seccomp | **위험 시스템 콜 53개**(`mount`·`setns`·`bpf`·`io_uring`·`keyctl`·커널 모듈·`perf_event_open`·`userfaultfd`, 대상이 gdb 를 건드리는 `pidfd_getfd`·`process_vm_*`·`kcmp` 등)와 `unshare`·네임스페이스를 만드는 `clone`·`clone3`, 비표준 소켓 계열(`AF_PACKET` 등) 차단. 디버거가 쓰는 `ptrace` 와 일반 `fork`·`mmap` 은 정상 |
| 디버거 보호 | 대상은 **gdb 와 같은 uid·같은 네임스페이스**에서 돌기 때문에, 막지 않으면 gdb 의 메모리·fd(호스트로 이어진 MI 파이프)를 건드려 **디버거 보고를 위조**할 수 있습니다(예: 실행 중인데 ‘종료됨’으로 보고). 그래서 gdb 를 네임스페이스의 PID 1(`--as-pid-1`)로 두고 `PR_SET_DUMPABLE=0`(gdb 의 Python 사용)으로 `/proc/<gdb>/{mem,fd}`·ptrace·`pidfd_getfd` 접근을 막습니다. 또 gdb 가 `SIGTERM`·`SIGHUP`·`SIGABRT`·`SIGBUS`·`SIGFPE`·`SIGSEGV`(gdb 가 스스로 핸들러를 거는 치명 신호까지) 를 무시해 대상이 `kill(1, 시그널)` 로 gdb(pid 1)를 죽여 분석을 방해하지 못하게 합니다. 시작 후 호스트에서 **실제로 적용됐는지 확인**하며, **확인하지 못하면 시작하지 않습니다**(gdb 에 Python 이 없거나 bubblewrap 이 0.8 미만인 경우). 위험을 감수하려면 카드의 ‘디버거 보호 없이 시작(이번 한 번)’을 선택하세요 — 저장되지 않고 보고서에 ✗ 로 표시됩니다. gdb 가 대상 종료 보고 없이 사라지면 정상 종료와 구분해 경고하고, 그 사유와 마지막 출력은 화면에 남습니다. **비용**: gdb 가 덤프 불가라 `/proc/<pid>/mem` 대신 ptrace 로 메모리를 읽어 큰 영역(`find`·`dump` 수십 MB)이 느립니다(약 10MB/s). 정지마다 gdb CPU 도 몇 배 듭니다 |
| 자원 한도 | 프로세스(스레드) 수·주소공간·**프로세스당 CPU 시간(대상 프로세스에만 — 디버거 자신은 제외, 감시가 한도를 넘은 대상만 SIGKILL)**·파일 크기·열린 파일 수·`/tmp` 크기·실행 시간, 낮은 우선순위(세션 자동그룹의 nice 포함). 모든 프로세스에는 감시가 멎었을 때를 위한 넉넉한 CPU 받침 한도(총 CPU 한도)가 따로 걸립니다. root 로 실행하면 cgroup 으로 총 메모리·프로세스 수도 — gdb·대상이 **실제로 cgroup 에 담겼는지 확인**하고, 담기지 않았다면 보고서에 미적용으로 표시합니다 |
| 총량 감시 | rlimit 는 프로세스마다 따로라 fork 하면 한도가 곱해지므로, 호스트에서 샌드박스 **전체의 CPU 시간 합계**(기본 1800초, 디버거 자신의 시간은 제외하고 대상이 만든 시간만, 아주 짧게 살다 죽는 자식의 시간까지 정확히 — 살아 있는 프로세스의 `utime+stime+cutime+cstime` 합), **메모리 합계**(`memory_mb`×2, Pss), 프로세스 수를 0.5초 간격으로 감시해 넘으면 세션을 끝냄. gdb 는 pid 로 식별해 메모리 합계에서 빼므로 대상이 `prctl(PR_SET_NAME)` 으로 이름을 바꿔도 소용없음 |
| 정리 | 세션이 끝나면 `setsid`·`SIGTERM` 무시 프로세스까지 모두 종료(pid 네임스페이스를 열린 fd 로 붙들어 번호 재사용으로 엉뚱한 프로세스를 죽이지 않음), 작업 폴더·cgroup 삭제. gdb 가 죽으면 남은 프로세스도 정리. 서버가 `SIGKILL` 로 죽어도 샌드박스는 남지 않고 다음 시작 때 잔재를 청소 |

- **격리를 쓸 수 없으면 시작하지 않습니다**(비격리로 조용히 바꾸지 않음). 이유와 해결 방법(설치·sysctl)이
  카드에 표시됩니다. 신뢰하는 파일이라면 **비격리**를 직접 선택할 수 있고, 그때는 확인창이 뜨며 **그 세션에만**
  적용됩니다(저장되지 않음).
- 카드의 `보호 층`은 **실제로 적용된 층**을 보여 줍니다. 권한이 없어 cgroup 이 빠졌거나 gdb 보호를 확인하지
  못했다면 그렇게 표시합니다.
- **네트워크**를 `호스트 공유`로 바꾸면 대상이 이 컴퓨터의 네트워크·로컬 서비스·추상 유닉스 소켓에 닿습니다(위험).
- **자원 한도**의 메모리는 대상 몫이며 gdb 몫(1GB)이 더해져 적용됩니다. 프로세스 수 한도는 계정의 `ulimit -u` 와
  이미 떠 있는 프로세스·스레드 수를 감안해 계산합니다. 한도는 `data/sandbox.json` 에 저장됩니다.
- **추가 읽기 전용 경로**: 격리에서는 호스트 파일이 보이지 않으므로, 실행 인자 `< 입력파일` 처럼 대상이 읽을
  파일의 폴더를 여기에 넣으세요(읽기 전용, 낮춘 uid 가 읽을 수 있어야 함). 다음은 거부됩니다: `/`·`/proc`·`/run`
  같은 커널·시스템 경로, `/etc`·`/home`·`/usr`·`/var`·`/tmp` **그 자체**(샌드박스가 정한 최소 루트를 되돌림),
  rework 데이터 폴더, `~/.ssh`·`~/.gnupg`·`~/.aws` 등 자격 증명 폴더를 **품은** 폴더(홈 전체 등), 그리고
  **소켓·FIFO·장치 파일·하위 마운트가 들어 있는 폴더**(호스트 프로세스의 UNIX 소켓에 연결하면 네트워크 차단을
  우회하므로). 폴더는 시작할 때마다 다시 검사하며 항목 2만 개를 넘으면 거부합니다. **주의**: 폴더는 *지금 내용 그대로* 연결되므로
  검사 뒤에 그 폴더에 다른 프로세스가 소켓 파일을 새로 만들면 대상이 닿을 수 있습니다. 같은 컴퓨터의 다른 사용자·프로그램이
  쓸 수 있는 폴더는 노출하지 말고, 입력 파일만 담은 **전용 폴더**를 만들어 쓰세요.
- **임시 폴더가 `noexec`** 로 마운트돼 있으면(보안 강화 배포판 등) 대상 복사본을 bind 하지 않고 샌드박스의 tmpfs 안에 내용을 복사해 넣습니다(실행 가능).
- **토큰 인증(선택, 공유 컴퓨터 권장)**: `run.py --require-token` 으로 실행하면 서버가 무작위 토큰을 만들어 접속 주소(`?token=…`)를
  출력하고, 모든 `/api` 요청에 토큰(HttpOnly·SameSite=Strict 쿠키 또는 `X-Rework-Token` 헤더)을 요구합니다. 같은 컴퓨터의
  다른 사용자·프로세스가 API(스크립트 실행·격리 끄기 포함)를 부르지 못합니다. **`네트워크: 호스트 공유` 는 토큰 인증이 켜져
  있을 때만** 시작할 수 있습니다(공유하면 대상이 `127.0.0.1` 의 이 서버에 닿아 격리를 끄고 다시 시작할 수 있으므로).
- **격리에서 달라지는 점**: 프로세스마다 주소공간 한도가 `메모리 + 1024MB`(gdb 몫)로 걸려 ASan·Go·JVM 처럼 수 GB 를 예약하는 프로그램은
  실패할 수 있습니다(메모리 한도를 올리세요). 대상은 `/sandbox/<이름>` 의 복사본으로 실행되므로 자기 경로 옆의 파일(`gcc` 의 `cc1`, `java` 의
  `libjli.so` 같은 설치 폴더)을 찾는 프로그램은 실패합니다 — 그 폴더를 ‘추가 경로’에 넣으세요. 프로세스(스레드) 수 한도는 이 계정의
  **다른 프로그램(브라우저·IDE)과 함께** 세므로 세션 중에 그것들이 스레드를 늘리면 대상의 `fork`·`pthread_create` 가 `EAGAIN` 으로 실패할 수 있습니다.
- **분석할 파일 크기 상한**: 열기·업로드는 기본 512MB 까지입니다(서버가 파일을 통째로 메모리에 올리고 파싱 결과가 몇 배가 되기 때문).
  `REWORK_MAX_FILE_MB` 환경 변수로 바꿉니다. 서로 다른 파일은 최근 8개까지만 메모리에 보관합니다. 아주 큰 함수(명령어 2만 개 초과)는
  의사코드를 만들지 않고 디스어셈블리만 보여 줍니다.
- 요구 사항: **리눅스 + bubblewrap**(`sudo apt install bubblewrap`), 사용자 네임스페이스 허용
  (Debian 계열 `kernel.unprivileged_userns_clone=1`, Ubuntu 24.04 `kernel.apparmor_restrict_unprivileged_userns=0`).
  seccomp 는 x86_64 에서 적용됩니다(다른 아키텍처는 나머지 층만). **Windows 는 WSL2 나 VM 안에서 rework 를
  실행**하세요(Windows 에는 이 격리가 없습니다). gdb 는 `/usr` 아래(배포판 패키지, Python 지원)여야 합니다.
- **한계(꼭 읽으세요)**: 이것은 *커널을 공유하는* 컨테이너급 격리이지 VM 이 아닙니다. 커널 취약점을 쓰는
  익스플로잇은 막지 못합니다. 실제 악성코드는 **격리 실행 + 일회용 VM** 을 함께 쓰세요. 또한 정적 분석
  (파일 열기·디스어셈블·디컴파일)은 rework 프로세스 안에서 파일을 **파싱**하며 격리되지 않습니다.
  seccomp 는 *차단 목록*(나머지 시스템 콜은 허용)이고, `/proc/self/mountinfo` 로 호스트 마운트 정보 일부(대상 복사본의 호스트
  경로·장치 이름)가 보이며, `/proc/<gdb>/{cmdline,status,stat}` 는 읽을 수 있고(민감 정보 아님), `/tmp` 는 바이트 수만
  제한되고 파일 개수는 제한되지 않습니다. 같은 uid 의 샌드박스들은 `RLIMIT_NPROC` 풀을 공유하므로 동시에 여러 세션을 띄우면
  서로의 프로세스 한도를 갉아먹을 수 있습니다(화면은 한 번에 하나만 엽니다). 일반 사용자(비 root) 환경에서는 cgroup 이
  보통 없어 **총량 감시가 1초 이내 근사**이고(빠른 메모리 폭주는 그 사이에 커질 수 있음), 탈출했다면 그 사용자의
  권한을 가집니다.
- **웹 방어**: 로컬 서버는 `Host` 헤더가 `127.0.0.1`·`localhost`·`[::1]` 이 아니면 거절하고(DNS rebinding),
  **API 요청**(POST 뿐 아니라 GET 도)이 **다른 출처의 웹페이지에서 온 것**(`Origin` 불일치·`Sec-Fetch-Site` 가
  `same-origin`/`none` 이 아님 — 같은 호스트의 다른 포트에서 도는 서비스의 페이지도 포함, 쿠키는 포트를 구분하지 않으므로)이면 거절합니다(업로드·본문 없는 POST 같은 CORS 사전 요청 없는 요청을 이용한 CSRF 차단).
  `curl`·스크립트처럼 그 헤더가 없는 요청은 통과합니다(그래서 위 토큰 인증이 있습니다). 같은 헤더가 여러 개인 요청은 거절하고,
  모든 응답에 `X-Frame-Options: DENY`·`frame-ancestors 'none'`(다른 사이트가 UI 를 iframe 으로 씌워 클릭을 유도하는 것 차단)·
  `nosniff` 를 붙이며, 외부 CDN 스크립트를 쓰는 자동 API 문서(`/api/docs`·`/redoc`)는 껐습니다.
  처리되지 않은 오류의 500 응답에도 같은 헤더가 붙고 경로·트레이스백은 응답에 싣지 않습니다. 업로드는 상한(`REWORK_MAX_FILE_MB`)을 넘으면 읽던 중에 끊고
  413 을 돌려줍니다. 토큰(`REWORK_TOKEN`)은 ASCII 여야 합니다. 토큰 인증이 꺼져 있고 이 컴퓨터에 다른 로그인 계정이 있으면 시작할 때 경고를 출력합니다.
  다른 호스트명이 필요하면 `REWORK_ALLOWED_HOSTS=이름1,이름2`.

## 빌드·테스트 러너

복구한 의사코드를 고쳐 **다시 컴파일하고 돌려 보는** 용도입니다. 하단 패널 **빌드·테스트** 탭(또는 `Ctrl+Shift+B`)에서 쓰며, 작업 폴더를 열어 둬야 합니다.
작업 폴더 내용으로 쓸 만한 작업을 짐작해 목록에 올리고(`Makefile` 의 `make`·`make test`…, `CMakeLists.txt`, `build.sh`·`test.sh`·`run.sh`, 단일 `.c` 파일, `pytest`·`unittest`, 파이썬 스크립트) 명령은 직접 고쳐 쓸 수도 있습니다.

**실행되는 코드는 신뢰할 수 없다고 봅니다**(악성코드에서 나온 코드일 수 있으므로). 그래서 기본은 디버거와 같은 bubblewrap 격리입니다.

| 항목 | 내용 |
| --- | --- |
| 복사-실행-되가져오기 | 작업 폴더를 격리의 `/work` 로 **복사**하고(`.git`·`node_modules`·심볼릭 링크·32MB 넘는 파일 제외, 최대 8000개·192MB) 거기서 `sh -c` 로 실행합니다. 원본은 건드리지 않습니다. 끝나면 **새로 생기거나 바뀐 일반 파일만** 검증해 되가져옵니다(빌드 결과물 등) |

## 노트북 (Jupyter 식 셀)

탐색기에서 `.ipynb` 를 열거나(**새 노트북**: 폴더 우클릭 또는 명령 팔레트 `>새 노트북`) 코드·글 셀을 편집하며 실행합니다. 분석 중에 “함수 목록을 뽑아 표로 보고, 마음에 드는 함수를 디컴파일해 보고, 결과를 기록으로 남기는” 흐름을 위한 것입니다.

- **커널**: 파이썬 코드 셀은 **상태가 유지되는 네임스페이스**에서 돌아 앞 셀의 변수를 뒤 셀이 씁니다. 마지막 줄이 식이면 IPython 처럼 값을 `Out[n]` 으로 보여 주고, `print` 출력은 실행하는 동안 조금씩 나타납니다. 중단(`⏹`)은 `KeyboardInterrupt` 를 넣어 파이썬 코드가 도는 동안만 듣습니다(C 확장 안에서 멈춘 것은 못 끊습니다 — 그때는 `↻ 재시작`).
- **분석 API**: 스크립트 콘솔과 같은 `rk`(`functions`·`name`·`xrefs`·`strings` …) 에 더해 `rk.decompile(addr)`(의사코드 문자열)과 `rk.table(rows, cols, limit)`(딕셔너리 목록을 표 글자로) 를 씁니다.
- **파일 형식**: nbformat 4(셀 `id` 포함)로 읽고 씁니다. 출력(스트림·`Out`·오류·PNG)도 함께 저장되고, 다시 열면 그대로 보입니다. 표준 Jupyter 가 만든 노트북도 열립니다.
- **출력 표시는 안전한 것만**: `text/plain`·스트림·오류·`image/png` 만 그립니다. **HTML 출력은 표시하지 않고**(안내만) 마크다운 셀도 DOM 으로만 만들어(제목·굵게·기울임·`코드`·목록·인용·코드 블록) 스크립트가 실행될 길이 없습니다.
- **저장**: `Ctrl+S`. 열어 본 뒤 디스크에서 바뀌었으면 덮어쓸지 묻습니다. 수정하면 탭에 ●, 닫을 때·창을 닫을 때 확인합니다. 이름을 바꾸거나 지우면 열려 있던 탭이 따라갑니다. 빌드·테스트 실행 전에 같이 저장합니다.
- **셀 편집**: 위/아래 이동·코드 ↔ 글 전환·삭제·아래에 추가, `모두 실행`(오류가 난 셀에서 멈춤), `🧹` 출력 모두 지우기. 커널은 서버에 하나뿐이라 한 번에 셀 하나만 실행하고, 여러 노트북이 같은 커널을 공유합니다.

> ⚠ **격리되지 않습니다(정직한 한계)**: 노트북 커널은 **서버 프로세스 안에서** 돌아 스크립트 콘솔(`/api/script`)과 같은 신뢰 모델입니다 — 분석가 본인의 코드를 위한 것입니다.
> 신뢰할 수 없는 코드는 위의 **빌드·테스트 러너(격리 실행)** 로 돌리세요. 그 밖의 한계: `.ipynb` 의 HTML·위젯·`display_data` 의 풍부한 형식은 그리지 않고, 셀의 `input()` 은 막히지 않고 바로 `EOFError` 를 내며(값은 코드에 직접 넣으세요), 커널은 파이썬 하나뿐입니다(다른 언어 커널·다른 가상환경 없음).
> 시험: `tests/test_notebook.py`(12개 시나리오 — 상태 유지·마지막 식·스레드별 출력·오류 프레임·중단·재시작·출력 상한·`rk`·실제 서버 API) 와 실제 Chromium 으로 셀 편집·실행·저장·보안 표시를 확인했습니다.

## 데스크톱 앱 (Windows·Kali)

`desktop/` 은 Electron 셸입니다. **분석 백엔드(Python)를 앱 안에 묶어(PyInstaller) 띄우고**, 그 UI 를 창에 보여 주며, 종료할 때 정리합니다.
사용자가 Python·pip 을 설치할 필요가 없습니다(디버거는 시스템의 `gdb`, 격리 실행은 `bubblewrap` 이 필요).

| 항목 | 내용 |
| --- | --- |
| 백엔드 수명주기 | 백엔드가 `--port 0` 으로 **미리 바인딩한 소켓**의 포트를 `REWORK_PORT=` 로 알립니다(포트를 알아냈다 닫는 경쟁 없음). 응답을 확인한 뒤 창을 띄우고, 앱이 어떻게 끝나든(`SIGKILL` 포함) 표준 입력 파이프가 닫혀 **백엔드가 스스로 종료**합니다(고아 프로세스·열린 샌드박스 없음). 백엔드가 죽으면 오류 화면(사유·로그)과 **다시 시작** 버튼 |
| 인증 | 앱이 시작마다 **무작위 토큰**을 만들어 백엔드에 **표준 입력**으로만 넘기고(명령줄·환경 변수 `/proc/<pid>/environ` 에 남지 않음), 창이 백엔드로 보내는 요청에만 헤더로 붙입니다(쿠키·주소·자바스크립트에 노출되지 않음). 같은 컴퓨터의 **다른 사용자 계정**은 포트를 알아도 API(스크립트 실행·격리 끄기 포함)를 부를 수 없습니다. 같은 계정으로 도는 다른 프로그램은 ptrace 등 다른 길이 있어 완전히 막지 못합니다(이 계정 전체를 믿는 모델 — 격리 실행된 대상은 네트워크가 막혀 닿지 못함) |
| 창 보안 | `contextIsolation`·`sandbox`·`nodeIntegration` 끔, 렌더러에는 최소 API(끌어다 놓은 파일의 경로·열기 결과 수신)만 노출. 백엔드 주소 밖으로의 이동·`file:`·`javascript:`·새 창 차단(`http(s)` 링크는 기본 브라우저로), 모든 권한 요청 거부, 시스템 프록시 미사용, 엄격한 CSP(같은 출처 스크립트만 — 분석 대상 파일에서 온 문자열이 어떻게든 HTML 이 돼도 실행되지 않음) |
| 실행 파일 강화 | Electron 퓨즈: `RunAsNode`·`NODE_OPTIONS`·Node 인스펙터 끔, asar 무결성 검증·asar 전용 로드 켬(`ELECTRON_RUN_AS_NODE` 로 앱을 범용 Node 로 쓰는 것 차단). 개발자 도구는 개발 모드에서만 |
| 데이터 | 사용자 폴더(`~/.config/rework`, Windows `%APPDATA%\rework`)의 `data/`(프로젝트·AI 설정 — 소유자 전용 0700/0600), `logs/backend.log`(토큰은 기록하지 않음), `config.json`(창 위치) |

**Windows**: 앱 안에 두 백엔드가 들어 있습니다. 기본은 **Windows 네이티브**(정적 분석 전부 — 디버거는 리눅스 전용이라 사이드바가 안내만 보여 줌).
메뉴 **실행 환경 > WSL2** 를 고르면 같은 앱이 **WSL2 안의 리눅스 백엔드**를 띄워 디버거·격리 실행까지 씁니다(WSL2 와 배포판 필요, `C:\` 는
`/mnt/c/` 로 자동 변환, 데이터는 WSL 홈의 `~/.rework/data`). 앱 종료·백엔드 사망 처리는 동일합니다.

> ⚠ **검증 범위**: Linux(Kali·Ubuntu) 설치본(`.deb`·AppImage)은 이 저장소 환경에서 빌드해 실제로 띄워 시험했습니다(`desktop/test/e2e_packaged.mjs` — `dist/linux-unpacked`·AppImage·`.deb`(시스템에 설치하지 않고 `dpkg-deb -x` 로 풀어서)에 같은 시험).
> 시험은 퓨즈·토큰·분석·격리 디버깅과 디버거 심화(메모리 맵·스택 덤프·로그포인트), 격리 러너(gcc 빌드·결과물 되가져오기), 노트북 셀 실행·저장, 백엔드가 죽었을 때의 오류 화면과 다시 시작, 종료 정리를 설치본의 동결 백엔드에서 확인합니다.
> **Windows 설치본은 이 환경에서 빌드·실행하지 못했습니다**(PyInstaller·electron-builder 는 크로스 빌드가 안 됨). Windows 용 코드(경로 변환·WSL2 실행·
> 드라이브 목록·POSIX 모듈 없이 임포트)는 단위·시뮬레이션 테스트만 거쳤고, 빌드는 `.github/workflows/desktop.yml`(수동 실행)이 Windows 러너에서 합니다. 첫 Windows
> 빌드·실행에서 문제가 나올 수 있으니 결과를 알려 주세요. 코드 서명이 없어 SmartScreen 경고가 뜹니다. 자동 업데이트는 없습니다(새 설치본으로 교체).
> AppImage 실행기(래퍼)는 앱(Electron)을 자식으로 띄우고 기다리는 프로세스라, **래퍼만 `kill` 하면 앱이 남습니다**(창을 닫거나 앱을 종료하면 백엔드까지 정리됩니다). 앱을 신호로 끝내려면 `rework` 본 프로세스에 보내세요.
> AppImage 는 사용자 네임스페이스를 쓸 수 없는 시스템(예: Ubuntu 24.04 기본 설정)에서 Chromium 샌드박스 없이(`--no-sandbox`) 시작합니다 — 그런 곳에서는 `.deb` 를 쓰세요.

릴리스 빌드는 `backend/requirements.lock`(테스트를 통과한 고정 버전)과 `desktop/package-lock.json` 으로 의존성을 고정합니다.

## 보안·범위

- 백엔드는 **127.0.0.1에만 바인딩**하는 로컬 전용 서버입니다(외부에서 접속 불가). `Host` 헤더도 로컬 주소만 허용합니다.
- 분석(디스어셈블·디컴파일)은 전부 이 컴퓨터에서 처리되며, **대상 바이너리를 실행하지 않습니다**(실행은 디버거뿐이고 기본이 격리 실행).
- 외부 통신은 AI 도우미를 직접 사용할 때만 일어납니다.
- 스크립트 콘솔은 분석가 본인의 파이썬을 격리 없이 실행합니다(대상 바이너리 실행과는 다름). 신뢰할 수 없는 스크립트는 붙여넣지 마세요.

### 디컴파일러 차분 시험

디컴파일러가 “그럴듯해 보이는” 결과가 아니라 **원본과 같은 동작**을 내는지를 기계로 확인합니다. `tests/decomp_corpus.c`(조건·루프·`switch`·포인터·구조체·재귀·상수 나누기·부동소수점·비트 연산·CRC·정렬·파싱·회전·오버플로 검사 등 118개 함수)를
컴파일해 각 함수를 디컴파일하고, 의사코드를 **다시 C 로 컴파일**해 같은 입력(경계값과 무작위 값)에서 반환값과 메모리 쓰기가 같은지 비교합니다.

- `tests/test_decomp.py`: 호스트 gcc 로 `-O0/-O1/-O2/-O3/-Os` 빌드, 호스트에서 직접 실행. 함수마다 별도 프로세스로 돌려 한 함수가 죽어도 나머지를 계속 시험합니다.
- `tests/test_decomp_emu.py`: clang `--target=…` + lld 로 x86‑64·x86‑32·ARM64·ARM 32비트(ARM·Thumb‑2, 소프트 플로트)·Windows x64(`ms_abi`)용 정적 바이너리를 만들어 **Unicorn 에뮬레이터**에서 원본을 실행하고, 의사코드는 호스트에서 컴파일해 비교합니다. 좁은 인자의 상위 비트에 쓰레기 값을 넣어 호출 규약 가정을 확인합니다.
  Unicorn 은 시험에만 쓰므로 런타임 의존성(`backend/requirements.txt`)에 넣지 않았습니다: `.venv/bin/pip install unicorn`. clang·lld·gcc 가 없으면 해당 시험을 건너뜁니다.

해석하지 못한 명령(SIMD·부동소수점)이 있거나 데이터 주소를 직접 읽는 함수는 “건너뜀”으로 세고 통과로 치지 않습니다. 현재 모든 아키텍처·최적화 수준에서 실행 가능한 함수는 전부 통과합니다.

실제 GDB로 `samples/demo_elf`를 디버깅하며 런타임 조작, MI 명령 주입 차단, 시작 실패·동시 종료 시
자원 정리, gdb 외부 종료, 재실행, 대상 stdin(한 줄·EOF·이스케이프·한글·한 줄 4095바이트 경계·리다이렉트),
출력 순서, MI 파서(8진 이스케이프·짝 안 맞는 괄호 퍼징)를 검증합니다. 입력 관련 시나리오는 `gcc`가
있을 때 작은 테스트 프로그램을 컴파일해 쓰고, 없으면 건너뜁니다.

`test_sandbox.py` 는 `tests/sbxprobe.c` 탐침을 컴파일해 **실제 격리 안에서** 호스트 파일·데이터 폴더·네트워크
(루프백·추상 소켓·외부)·호스트 프로세스·금지 시스템 콜·중첩 user namespace 에 접근해 보고, fork 폭탄·메모리·CPU·
파일 크기·`/tmp` 채우기·열린 파일·실행 시간 한도, 정리(setsid·SIGTERM 무시 데몬, 서버 SIGKILL)를 검증합니다.
각 항목은 **격리를 끈 대조군**과 비교해(예: `network=host` 면 호스트 루프백에 닿음) 통과가 우연이 아님을 보입니다.
적대적 검토(레드팀)에서 나온 문제 — 대상이 gdb 를 조작해 거짓 보고를 보냄, 스레드 풀 작업자가 사라지며 세션이 죽음,
네임스페이스 번호 재사용으로 엉뚱한 프로세스를 죽임, fork 로 CPU·메모리 한도가 곱해짐, 폴더 안 소켓 노출, 다른 계정이 읽는
복사본, 출력 폭주 — 는 각각 회귀 테스트로 고정했습니다. 비 root 사용자로도 같은 테스트를 통과합니다.
